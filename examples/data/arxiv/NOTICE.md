# arXiv example dataset

50,000 arXiv papers with two 2D layouts, Toponymy's four levels of named clusters, and arXiv's own classification. The files are Parquet, compressed with zstd. `schema.toml` declares them as a Mosaica corpus, and `manifest.json` records the row count of every file.

## What is here

| file | rows | contents |
|---|---|---|
| `points.parquet` | 50,000 | `entity_id`, `x`, `y` (the `topics` view), `categories` (the access terms), `arxiv_id`, `archive`, `primary_category`, `submitted_at`, `title` |
| `points-umap200.parquet` | 50,000 | `entity_id`, `x`, `y`, `categories`: a second layout of the same papers (the `topics-wide` view) |
| `archive.parquet`, `primary_category.parquet` | 38, 171 | arXiv's archives and subject classes, copied whole from the source |
| `clusters-toponymy.parquet` and members | 797 | Toponymy's four levels of clusters |
| `taxonomy-arxiv.parquet` and members | 201 | arXiv's own classification: archives over subject classes |
| `topics-toponymy.parquet` and members | 797 | a name for each Toponymy cluster |

The papers carry no abstracts. The names' member file lists, for each name, the papers the language model was shown, which a reader must be able to see before the name is served to them.

## Where it came from

The papers are a cut of `data/notebook-2m4-live`, the 2,422,486-paper notebook corpus, which joins two sources:

- the arXiv metadata snapshot published by Cornell University on Kaggle (`Cornell-University/arxiv`, version 296), which gives each paper's identifier, title, categories and submission date;
- [AliMaatouk/arXiv-Topics-Embeddings](https://huggingface.co/datasets/AliMaatouk/arXiv-Topics-Embeddings) on Hugging Face, one BGE-large-en-v1.5 embedding per paper. Its card says these are embeddings of [AliMaatouk/arXiv_Topics](https://huggingface.co/datasets/AliMaatouk/arXiv_Topics), whose topic labels, at three levels, were generated by prompting GPT-4o. Neither card says which text of the paper GPT-4o was given.

`probes/build_corpus.py` joined the two. The first layout (`x`, `y` in `points.parquet`, stored as `float32`) is UMAP over the embeddings reduced by PCA to 64 components, with 15 neighbours and a minimum distance of 0.1, unseeded, over the whole corpus. The Toponymy clustering was computed over that layout, also over the whole corpus.

The second layout, `points-umap200.parquet`, was made for this dataset from the same embeddings: PCA to 64 components, then `umap-learn` with 200 neighbours, a minimum distance of 0.9 and seed 0, over the 50,000 sampled papers only.

The Toponymy names were written by a language model (Qwen3.6-35B-A3B) through the [Toponymy](https://github.com/TutteInstitute/toponymy) library. For each cluster the model was shown the titles of six exemplar papers near the cluster's centre, keyphrases drawn from the titles of the cluster's papers, and, above the finest level, the names of the clusters beneath it. It was shown no abstracts. Each name's member file lists its six exemplars.

The sample keeps every Toponymy exemplar, 4,284 papers, so that each name ships with every paper it was written from. The other 45,716 papers are a uniform draw, with seed 0, from the rest of the corpus. Every clustering and member file is restricted to the sampled papers, and the taxonomy drops the 8 archives and subject classes with no sampled paper. The archive and subject-class vocabularies are copied whole.

## Making it again

From the repository root, with `data/notebook-2m4-live/`, `data/corpus.parquet` and `data/arxiv_papers_embeds.parquet` present and `scikit-learn` and `umap-learn` installed:

```bash
python -m test_corpora.arxiv.example --source data/notebook-2m4-live --out examples/data/arxiv --papers 50000 --seed 0
```

It takes about five minutes, most of it reading the 4.7 GB embedding file and laying out the second view. The first layout and the Toponymy clusters and names are copied from the source, which was made once and cannot be reproduced exactly, so the command makes this dataset again only from that same source directory.
