# notebook's CPU path is reproducible under a fixed `random_state` — umap-learn falls back to a
# single thread when one is given — which is what lets the notebook be the definition of its own
# output rather than a step whose result has to be archived.

# **The `hdbscan` package rather than scikit-learn's HDBSCAN**, and the reason is the whole point of

# hierarchy. scikit-learn's implementation gives labels and a single-linkage tree, from which the
# cluster hierarchy would have to be reconstructed — a reimplementation of the algorithm's own
# output, and a place for this notebook to disagree with the literature.
